# Experiment Architecture Specification

**Purpose:** Define how experiments are structured, registered, parameterized, and run
in the SHADED post-GOLD research pipeline. Every experiment must be reproducible from
an `ExperimentCard` (JSON + git commit + run ID).

---

## 1. Core Concepts

### 1.1 ExperimentCard (single source of truth)

```jsonc
{
  "experimentId": "exp-001",
  "version": "1.0",
  "title": "DepthAnything-V3 vs V2 Depth Quality",
  "description": "Compare monocular depth quality on 5 hall scenes",
  "runId": "run-20260820-190600Z",         // GOLD_FREEZE.md §12
  "gitRef": {
    "repo": "SHADED",
    "commit": "b341f7f46390216e81c97e01259a573fd2e9896c",
    "tree": "ff1d67176d0a99c715416e29cc31098aad1a0147"
  },
  "operator": "DepthProvider",             // from EG_DONOR_MATRIX
  "donor": "Depth Anything V3",
  "mode": "research",                      // gold | research | teacher
  "parameters": {
    "depth_model": "depth_anything_v3",
    "input_resolution": 512,
    "batch_size": 1
  },
  "inputs": [
    {
      "type": "image",
      "path": "file_00000000974871f49fe71f6b456f9579.png"
    }
  ],
  "outputs": [
    {
      "kind": "depth_map",
      "path": "artifacts/run-20260820-190600Z/exp-001/depth_v3.png"
    }
  ],
  "metrics": [
    { "name": "depth_mse_mm", "threshold": 25.0 },
    { "name": "depth_edge_f1", "threshold": 0.70 }
  ],
  "expectedClassCounts": {
    "dorf-marker": {"foliage": 5872, "grass": 4885, "wood": 3636, "rock": 1186, "roof": 2818, "window": 197, "path": 2142}
  },
  "timeoutSeconds": 300,
  "retries": 1
}
```

### 1.2 Run ID

Format: `run-YYYYMMDD-HHMMSSZ` (UTC). Generated by `node tools/orchestrate.js`
using the GOLD environment as epoch. Must match `GOLD_FREEZE.md` §12.

### 1.3 Mode

| Mode | Meaning | Effect on SHADED |
|---|---|---|
| `gold` | Baseline configuration | No operators active; GOLD params only |
| `research` | Experimental operator enabled | Operator may override or supplement default behavior |
| `teacher` | Training/analysis only | Teacher output compared against GOLD, never affects delivery |

    "dependencies": ["node:v22", "torch:2.3"],

## 3. Experiment Engine

### 3.1 Entry Point

```bash
node tools/orchestrate.js --experiment docs/research/experiments/exp-001.json --output artifacts/ --log-level info
```

### 3.2 Engine Flow

```
ExperimentCard (JSON)
  → validate card against operators.json schema
  → git checkout card.gitRef.commit
  → npm ci (if node_modules absent)
  → install operator dependencies (if needed)
  → execute operator(card.parameters, card.inputs)
  → collect outputs to card.outputs
  → compute metrics against thresholds
  → compare class counts to card.expectedClassCounts
  → write results to artifacts/<runId>/<expId>/
  → return exit code: 0=pass, 1=metric fail, 2=error, 3=class regression
```

### 3.3 Operator Execution

Each operator exposes a standard interface:

```ts
interface Operator {
  id: string;
  run(card: ExperimentCard, ctx: RunContext): Promise<OperatorResult>;
  validateInputs(card: ExperimentCard): boolean;
  validateOutputs(result: OperatorResult, card: ExperimentCard): boolean;
}

interface RunContext {
  gitRef: GitRef;
  scratchDir: string;
  artifactDir: string;
  log: Logger;
}

interface OperatorResult {
  outputs: ExperimentOutput[];
  metrics: MetricResult[];
  classCounts: Record<string, number>;
  logs: string[];
}
```

### 3.4 Isolation

- Operators run in subprocesses (not the main process) to prevent contamination.
- Each run gets a fresh `scratch/` directory.
- `node_modules` is isolated per-run unless `sharedNodeModules: true` is set.

### 3.5 Metrics Contract

| Metric | Source | Threshold field | Pass condition |
|---|---|---|---|
| `depth_mse_mm` | Operator | `threshold` | MSE ≤ threshold |
| `depth_edge_f1` | Operator | `threshold` | F1 ≥ threshold |
| `class_count_delta` | SHADED verify regression | ±10% (min 40) | Within tolerance |
| `render_fps` | index.html shader | `threshold` | FPS ≥ threshold |
| `console_errors` | index.html | 0 | No GL errors |
| `provenance_complete` | ProvenanceTracker | 1.0 | 100% tracked |

## 6. Operator Toggle Mechanism

Operators are enabled/disabled via environment variables or CLI flags:

```bash
# Enable DepthProvider with V3 model
SHADED_OP_DEPTH_PROVIDER=model:depth_anything_v3 RES=512 node tools/orchestrate.js ...

# Disable all research operators (pure GOLD)
SHADED_OPS=none node tools/orchestrate.js ...
```

Toggle convention: `SHADED_OP_<OPERATOR_NAME>` = comma-separated `key:value` pairs.
Setting to `disabled` turns off the operator.

### 6.1 Operator Composition

Operators declare dependencies/consumes/produces in `operators.json`:

```jsonc
"GaussianRepresentation": {
  "consumes": ["GeometryObservation.points", "DepthProvider.depth"],
  "produces": ["GaussianCloud"],
  "requires": ["torch:2.3", "cuda:11.8"]
}
```

The engine resolves dependency order automatically (topological sort of the operator graph).

## 7. Reproducibility Requirements

1. **Git-pinned**: Every experiment records the exact `commit` and `tree` hash.
2. **Environment-pinned**: `GOLD_FREEZE.md` records Node/npm/Chromium versions.
3. **Dependency-pinned**: `package-lock.json` pins all npm deps; operator deps use
   pinned versions in `operators.json`.
4. **Output-hashed**: Every artifact gets a SHA-256 hash recorded in `result.json`.
5. **Seed-fixed**: Every stochastic operator records its seed.

---

## 8. Integration Points with SHADED Core

| Component | Integration mechanism |
|---|---|
| `index.html` shader | Operators that override rendering run as **external pre-processors** that generate new input images; the shader is never duplicated |
| `analyze()` classification | Must be preserved exactly; operators that change materials write **companion files** (`_shading.png`, `_depth.png`) |
| `window.SHADED.addActor()` | Operator output (sprite sheets) consumed via manifest on `#ov` overlay canvas |
| `window.SHADED.intrinsic.set()` | Teacher operators write shading field companion; never bypass the intrinsic API surface |
| Spatial kernel | Operators register via `CompletionProviderRegistry` or direct `kernel.ingest(observation)` |

## 9. CLI Contract

```bash
node tools/orchestrate.js --experiment <path> [--output <dir>] [--dry-run] [--list-operators]
```

| Flag | Action |
|---|---|
| `--experiment <path>` | Load ExperimentCard JSON |
| `--output <dir>` | Output directory (default: `artifacts/`) |
| `--dry-run` | Validate card + operator availability, no execution |
| `--list-operators` | Print registered operators from `operators.json` |
| `--log-level <level>` | `error|warn|info|debug` |
| `--timeout <seconds>` | Override card timeout |

**Exit codes:** 0=pass, 1=metric fail, 2=execution error, 3=class regression.

---

## 10. Non-Goals

- No operator may **redefine** the material truth (`analyze()` output). Teachers
  produce **external companions**, not second classification paths.
- No operator may **fork the shader**. New backends produce input images/textures.
- No operator may **mutate GOLD** without producing an explicit diff + audit.
- No operator needs to pass the full `npm run check` suite; only the experiment
  engine's own validation.
